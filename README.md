本项目代码采用 [MIT 许可证](LICENSE)；用户主动下载的第三方组件不包含在仓库或安装包中，分别遵守各自的上游许可证。

一个用于局域网技术交流与测试的桌面工具。核心功能是本地 DNS / HTTPS 网页服务，并提供用户主动下载第三方组件、发送 ELF 和通过 PKG Manager 安装本地 PKG 的操作入口。

**本项目不是 PS5 破解程序。仓库与安装包不捆绑 PS5 漏洞利用程序、破解脚本、第三方 ELF 或游戏资源。** 第三方组件只记录上游来源，用户点击后才下载；网页内容由使用者自行选择来源。服务启动、收到 PS5 请求或 ELF 已发送均不代表第三方程序安装或执行成功。

## 开发与构建

上游协议适配已实现；真实 PS5 上的结果以实机验证记录为准。

需要 Node.js 22.12 或更新版本。安装依赖后，Electron 44 需要运行一次 `node node_modules/electron/install.js` 下载桌面运行时：

```bash
npm install
node node_modules/electron/install.js
npm start
```

测试和打包：

```bash
npm test
npm run pack:dir
npm run pack:mac
npm run pack:win
```

`pack:mac` 在 macOS 上生成 DMG 和 ZIP；`pack:win` 生成 NSIS 和 portable 包。正式分发所需的 macOS 签名、公证和 Windows 签名需要发布者自己的凭据。本项目不包含这些凭据。

推送到 GitHub `main` 分支或手动运行 [Build desktop packages](https://github.com/MarcusYuan/ps5-lan-workbench/actions/workflows/build.yml)，会分别构建 Windows x64 安装版、便携版和 macOS DMG、ZIP；下载文件在该次 Actions 运行的 Artifacts 中。自动构建不签名、不发布 GitHub Release。macOS 未签名包可能被 Gatekeeper 拦截，正式分发前仍需签名、公证及实机验证。

## 使用

1. 让电脑和 PS5 连接同一路由器，在应用里选择面向 PS5 的 IPv4 网卡。
2. 粘贴公开 GitHub 仓库根地址，例如 `https://github.com/owner/repository`，或 HTTPS ZIP 直链。GitHub 仓库会先解析默认分支的确切提交，再下载归档。Release 页面本身不是 ZIP 地址；请使用该 Release 的 ZIP 直链。
3. 输入归档中的网页入口相对路径，默认 `index.html`。点击“下载并检查”。解压内容存放在应用用户数据目录；失败或取消会保留上一份可用文件。
4. 点击“启动本地服务”。应用监听所选网卡的 UDP/TCP 53、HTTPS 443 和 HTTP 8000。若系统要求管理员授权，按系统提示操作。端口被其他程序占用时应用会报告错误。
5. 在 PS5 网络设置中将主 DNS 设为应用显示的电脑 IPv4 地址。通过 PS5 用户指南入口尝试访问网页。HTTP 地址只用于电脑或局域网测试。
6. 查看“PS5 HTTPS 访问”状态与请求日志。此状态只表示收到了带 PlayStation/PS5 浏览器标识的 HTTPS 请求，不表示证书已被 PS5 信任，也不表示破解成功。

### 插件与本地 PKG

下载 GitHub 资源较慢时，可在“文件来源”中开启“GitHub 镜像加速”。开关同时用于网页仓库 API、ZIP 和插件附件，重启后保留选择，默认关闭；切换仅影响新下载，不中断当前任务。无需配置系统代理，不改变 DNS/HTTPS 或 PS5 连接。

镜像使用第三方 [GH-Proxy](https://gh-proxy.com/docs/github-accelerator/) 的 `gh-proxy.org` 下载入口，服务商会收到所请求的公开 GitHub 资源地址。不转发账号凭据或带查询参数的地址，不处理其他站点 ZIP；插件仍严格校验内置 SHA-256。普通网页 ZIP 没有预置可信摘要，请自行信任其来源及镜像服务。镜像可用性和速度取决于网络，失败时可关闭开关后重试，不会自动更换下载线路。

1. 在顶部单独填写 PS5 IPv4 地址并保存；保存不会检测主机。电脑网卡 IP 继续用于本地 DNS/HTTPS。
2. 在“安装插件”区查看上游来源，点击“下载”后应用校验固定发布附件的 SHA-256。下载完成后可单独点击“加载到 PS5”；此时才检测默认 9021 并发送 ELF。WebKit Autoloader 的实际安装结果需在 PS5 上确认；PKG Manager 通过 8844 接口验证就绪。
3. 在“安装本地 PKG”区选择或拖入电脑上的单个 `.pkg`。点击“安装到 PS5”后才检查默认 8844，使用 PKG Manager Direct Install 分段传输。此流程无需 SMB 共享，也不依赖 9021。请保持电脑和源文件可用，直到 PS5 返回安装结果。

在 7.00–13.60 固件上，WebKit Autoloader 的默认 ELF Loader 可能仅接受 PS5 本机连接。需要从电脑发送 ELF 时，应先按[上游说明](https://github.com/itsPLK/ps5-webkit-autoloader/blob/v0.5.0/README.md)启用可从局域网连接的 ELF Loader。Payload Manager 与 PKG Manager 是不同程序。

如果 53 端口被本机其他 DNS 或代理软件占用，可用 `--diagnostic-ports` 启动应用，仅在电脑侧临时测试 DNS 5354、HTTPS 8443、HTTP 18000 的启动与页面读取。关闭应用后正常启动即恢复默认 53/443/8000；PS5 的 DNS 设置不能指定 5354，因此诊断模式不能用于 PS5 实机访问。

macOS 可运行 `"/应用路径/PS5 Local Host.app/Contents/MacOS/PS5 Local Host" --diagnostic-ports`，Windows 可运行 `"PS5 Local Host.exe" --diagnostic-ports`。开发环境使用 `npm start -- --diagnostic-ports`。

本机证书是应用自动生成并保存的自签证书，包含目标域名 SAN。域名变化或证书临近过期时会重新生成。应用不会将它安装成系统根证书。PS5 13.60 对首次证书提示、页面入口路径和后续网页行为仍需实机验证；目前状态为 **13.60 待验证**。

## 网络行为与数据

- DNS 仅将设置中的目标域名（默认 `manuals.playstation.net`）的 A 查询回答为所选本机 IPv4；AAAA 没有地址；其他域名返回 NXDOMAIN。DNS 不转发公网请求。
- HTTPS 和 HTTP 托管同一份用户下载的网页文件。用户指南 `/document/<语言>/ps5/` 路径重定向到所选入口；缺失文件返回 404。
- 除用户主动下载资源外，服务本身只使用本地网络；用户提供的网页或脚本可能自行发起外部请求，其行为取决于第三方内容。若要验证离线行为，可下载完毕、启动服务后断开电脑外网，并保持电脑与 PS5 之间的局域网连接。
- 第三方组件只在用户点击下载时从固定上游 HTTPS 发布附件获取（开启镜像时经镜像下载）；PKG 数据只在用户点击安装后送往填写的 PS5 IP。选择文件和保存 IP 不会发起网络检测。
- 配置、资源和私钥保存在 Electron 的用户数据目录，不进入安装包。服务关闭后不会自动恢复监听，需要手动启动。
